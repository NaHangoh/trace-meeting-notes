# 요구사항 명세 (1차 버전)

## 목적
회의 스크립트를 회의록으로 정리하되, 모든 항목을 원문 발언에 연결하고 근거 없는 내용을 사용자가 확인한 뒤에만 최종 회의록에 남긴다.

## 범위 (1차)
- 텍스트 스크립트 입력 (붙여 넣기, .txt 업로드). 화자 표시(`이름:`)가 있으면 인식
- 기본 회의록 형식: 안건 / 논의 내용 / 결정 사항 / 할 일(담당자, 기한)
- 정리 → 검증 (서로 다른 단계, 서로 다른 프롬프트)
- 검토 화면: 항목별 원문 근거 강조, "근거 없음 / 근거 약함" 표시, 항목 수정·삭제·유지
- 확정 후 워드(docx) 다운로드
- 반응형 웹, PWA 설치

## 범위 밖 (1차)
- 음성 파일 입력, 실시간 녹음
- 로그인, 회의록 보관함, 공유 링크
- 한글(hwp), 엑셀(xlsx) 내보내기 → 2차
- 사용자 정의 템플릿 → 2차

## 기능별 수용 기준
### F1. 스크립트 입력

#### 목적
붙여 넣거나 업로드한 회의 스크립트를 번호 붙은 발언 목록으로 나눈다. 이후 정리·검증·검토의 근거 위치는 모두 이 번호를 기준으로 한다.

#### 사용자 흐름
1. 입력 화면에서 스크립트를 붙여 넣거나 .txt 파일을 고른다. 파일은 브라우저에서 읽어 입력란에 채운다 (업로드 API 없음).
2. 입력이 바뀌면 500ms 디바운스 후 미리보기 API를 호출하고, 정리 시작 버튼 옆에 요약 한 줄을 보여준다. 예: `발언 132개 · 화자 4명 (김민수, 이영희, 박준호, 미상)`
3. 정리 시작을 누르면 서버가 입력을 다시 검사·분할하고 작업 ID를 돌려준다. 별도 미리보기 화면이나 확인 단계는 없다.

#### 입력·출력
- 입력: 텍스트(붙여 넣기) 또는 .txt 파일
- 분할 결과: `[{ no, speaker, text }]`. `no`는 1부터 빈틈없이 이어진다.
- 미리보기 API: `POST` 요청에 텍스트를 받아 `{ utteranceCount, speakers }`만 돌려준다. 발언 본문은 응답에 넣지 않는다. 입력과 결과를 저장하지 않고, 본문을 로그에 남기지 않는다.
- 분할 로직은 백엔드에만 둔다. 프론트는 분할하지 않고 미리보기 API 결과만 표시한다.
- 미리보기 API 요청 수 제한: IP당 분당 60회, 넘으면 429. 정리 요청 제한(S4)과 별도 설정값.

#### 분할 규칙
- 줄바꿈(`\r\n`, `\n`)으로 줄을 나누고, 줄마다 발언 번호를 따로 붙인다.
- 빈 줄·공백만 있는 줄은 번호를 받지 않는다. 화자 이어받기는 끊기지 않는다.
- 화자 표시가 있는 줄은 그 화자, 없는 줄은 바로 앞 발언의 화자를 이어받는다. 이어받을 화자가 없으면 "미상".
- `김민수:`처럼 화자만 있고 내용이 빈 줄은 번호를 받지 않고, 다음 줄부터 그 화자를 이어받는다.
- 화자 표시 인정 조건: 줄 맨 앞에서 첫 콜론까지(앞뒤 공백 제외, 연속 공백은 한 칸으로 합친 뒤)가 1~20자이고 공백 기준 2단어 이하. 공백은 전각 공백(U+3000)을 포함한다. 다만 다음은 화자로 보지 않는다.
  - (a) 콜론 바로 앞 글자와 바로 뒤 글자가 모두 숫자 (예: `시간은 10:30으로`)
  - (b) 콜론 앞에 글자(`Character.isLetter`)가 하나도 없음 (예: `2024:`, `10.5:`, `2024 1:`)
  - (c) 콜론 앞 단어 중 하나라도 머리말 목록(참고, 결론, 비고, 안건, 결정, 메모, 주의, 요약)에 있음 (예: `결정 사항:`, `회의 요약:`). 목록은 코드 상수 하나로 관리한다.
- 화자 이름은 연속 공백(전각 포함)을 한 칸으로 합친다. `김민수  팀장`과 `김민수 팀장`은 같은 화자다.
- 숫자·글자 판정은 문자(코드 포인트) 단위로 한다.
- 화자로 보지 않는 줄은 줄 전체가 발언 내용이 되고 앞 화자를 이어받는다.
- 화자 목록 순서는 처음 나온 순서이며 "미상"은 항상 마지막.
- 최대 길이: 50,000자(줄바꿈을 `\n`으로 정규화한 뒤 문자 수). 설정값이며 S3와 같은 값.

#### 파일 읽기 (프론트)
- 파일은 브라우저에서 읽는다. 업로드 API는 만들지 않는다.
- 파일 검사: 확장자 .txt, 200KB 이하, NUL 문자(`\0`) 없음. 하나라도 어기면 거부하고 이유를 안내한다. NUL 문자가 있으면 텍스트 파일이 아닌 것으로 본다.
- 인코딩: `new TextDecoder('utf-8', { fatal: true })`로 먼저 읽고, 실패하면 `new TextDecoder('euc-kr', { fatal: true })`로 읽는다. 둘 다 실패하면 "읽을 수 없는 인코딩"이라고 안내하고 입력란에 채우지 않는다. UTF-8 BOM은 결과에 남지 않는다.

#### 서버 검사
- 서버는 받은 텍스트를 다시 검사한다 (미리보기·작업 생성 모두): 길이 50,000자 이하, NUL 문자 없음, 요청 본문 바이트 상한(200KB, 설정값) 이하. 오류 응답에 입력 본문을 넣지 않는다.
- 공백 판정: `Character.isWhitespace` 또는 `Character.isSpaceChar`인 문자를 공백으로 본다 (NBSP·전각 공백 포함). 검사와 분할이 같은 기준을 쓴다.
- 응답 코드: 빈 입력·글자 수 초과·NUL 문자·분할 결과 발언 0개는 400, 요청 본문 바이트 상한 초과는 413, 요청 수 초과는 429.

#### 수용 기준
- [ ] 빈 입력·공백만 있는 입력이면 정리 시작 버튼이 비활성화되고 안내 문구가 나온다. 서버도 400으로 거부한다. NBSP(U+00A0)만 있는 입력도 공백만 있는 입력이고, NBSP만 있는 줄은 번호를 받지 않는다.
- [ ] 화자 줄만 있어 발언이 0개인 입력(예: `김민수:`)은 미리보기·작업 생성 모두 400으로 거부한다.
- [ ] 줄마다 발언 번호가 1부터 빈틈없이 붙고, 빈 줄·공백만 있는 줄은 번호를 받지 않는다.
- [ ] `김민수: 일정은요` 다음 줄 `다음 주까지 가능합니다`는 2번 발언, 화자 김민수가 된다.
- [ ] 첫 줄에 화자 표시가 없으면 화자는 "미상"이다.
- [ ] `김민수:`만 있는 줄은 번호를 받지 않고, 다음 줄 발언의 화자가 김민수가 된다.
- [ ] (a) `김민수: 시작합니다` 다음 줄 `다음 회의는 10:30으로 하죠`는 화자 김민수, 내용은 줄 전체가 된다. `시간은 10:30으로`는 화자로 인식하지 않는다. `김민수:3시에 보죠`는 화자 김민수로 인식한다.
- [ ] (b) `2024: 매출 목표 달성`, `10.5: 증가`, `2024 1: 실적`은 화자로 인식하지 않는다. `참석자 1: 네`는 화자 "참석자 1"로 인식한다.
- [ ] (c) `참고: 다음 주 마감입니다`는 화자로 인식하지 않는다. 머리말 상수의 모든 단어에 대해 같은 결과가 나온다(매개변수화 테스트). `결정 사항: A안 채택`, `회의 요약: 다음 주 마감`도 화자로 인식하지 않고 앞 화자를 이어받는다.
- [ ] `김민수  팀장: 네`(연속 공백)와 `김민수 팀장: 네`는 같은 화자 "김민수 팀장"이다. 전각 공백도 공백으로 센다.
- [ ] 경계: 줄 앞 공백이 있어도 화자로 인식한다. 콜론이 맨 앞인 줄은 화자가 아니고 줄 전체가 내용이다. 콜론 뒤가 공백뿐이면 번호 없이 화자만 바뀐다. 마지막 줄이 화자만 있으면 발언이 생기지 않고 화자 목록에도 들어가지 않는다.
- [ ] 콜론 앞이 20자를 넘는 줄은 화자로 인식하지 않는다.
- [ ] 2단어 조건: `이영희: 정리하겠습니다` 다음 줄 `결정 사항은 다음과 같습니다:`는 화자가 바뀌지 않고 이영희를 이어받으며, 내용은 줄 전체다. `김민수 팀장: 네`는 화자 "김민수 팀장"으로 인식한다.
- [ ] 미리보기 API는 발언 수와 화자 목록(순서 포함)만 돌려주고, 같은 입력으로 작업을 만들었을 때의 분할 결과(발언 수, 화자 목록)와 같다.
- [ ] 미리보기 API 호출 후 저장소에 남는 데이터가 없고, 로그에 입력 본문이 남지 않는다.
- [ ] 프론트는 입력이 멈춘 뒤 500ms가 지나야 미리보기 API를 한 번 호출한다(연속 입력 중에는 호출하지 않음).
- [ ] 미리보기 API가 400 또는 429를 돌려주면 프론트는 요약 줄을 숨긴다.
- [ ] 작업 생성 요청이 429를 받으면 프론트는 "잠시 후 다시 시도" 안내를 보여준다.
- [ ] 50,000자를 넘으면 프론트는 현재 글자 수와 상한을 보여주고 시작을 막는다. 서버는 미리보기·작업 생성 모두 400으로 거부하고, 오류 응답에 입력 본문을 넣지 않는다.
- [ ] 같은 IP에서 1분 안에 미리보기 API를 61번째 호출하면 429를 돌려준다. 이 상한은 정리 요청 제한(S4)과 다른 설정값이다.
- [ ] 요청 본문이 200KB를 넘는 미리보기·작업 생성 요청은 413으로 거부한다.
- [ ] NUL 문자(`\0`)가 든 텍스트를 서버에 직접 보내면 미리보기·작업 생성 모두 400으로 거부한다.
- [ ] (프론트 Vitest) UTF-8로도 euc-kr로도 디코딩되지 않는 바이트는 입력란에 채우지 않고 "읽을 수 없는 인코딩" 안내를 보여준다.
- [ ] (프론트 Vitest) CP949(euc-kr)로 인코딩한 바이트를 읽으면 같은 내용을 UTF-8로 인코딩한 바이트와 같은 문자열이 된다.
- [ ] (프론트 Vitest) UTF-8 BOM이 있는 파일을 읽으면 결과 문자열이 BOM으로 시작하지 않는다.
- [ ] (프론트 Vitest) .txt가 아닌 파일, 200KB를 넘는 파일은 입력란에 채우지 않고 이유를 안내한다.
- [ ] (프론트 Vitest) NUL 문자가 든 파일은 입력란에 채우지 않고 텍스트 파일이 아니라는 안내를 보여준다.

#### 범위 밖
- `이름:` 외 화자 형식: 타임스탬프(`[00:12:34] 이름:`), 이름 다음 줄에 발언이 오는 형식
- 분할 결과·화자를 화면에서 고치는 기능, 별도 미리보기 화면
- .txt 외 파일(docx, hwp, srt, vtt), 음성 입력

### F2. 정리
- [ ] 결과의 모든 항목은 하나 이상의 발언 번호를 근거로 가진다 (없으면 근거 없음으로 표시).
- [ ] LLM이 준 발언 번호가 실제로 존재하지 않으면 그 근거는 버리고 항목을 근거 없음으로 바꾼다.
- [ ] 긴 스크립트는 나눠서 처리하고 결과를 합친다. 나눈 경계에서 발언 번호가 어긋나지 않는다.

### F3. 검증
- [ ] 정리 결과의 각 항목을 근거 발언과 대조해 "근거 있음 / 근거 약함 / 근거 없음"으로 판정한다.
- [ ] 검증은 정리와 다른 호출로 실행한다.

### F4. 검토 화면
- [ ] 항목을 선택하면 해당 원문 발언이 강조되고 화면에 보인다.
- [ ] 근거 없음·근거 약함 항목은 아이콘과 문구로 구분된다 (색만으로 구분하지 않음).
- [ ] 항목을 수정, 삭제, 유지할 수 있다.

### F5. 확정과 내보내기
- [ ] 확인하지 않은 근거 없음 항목이 있으면 다운로드 전에 개수를 알리고 확인받는다.
- [ ] docx에는 확정된 회의록 내용만 들어간다. 발언 번호, 근거, 검증 표시는 들어가지 않는다.
- [ ] docx 문서 속성(작성자, 생성 프로그램)에 도구 이름이 남지 않는다.

## 비기능
- 정리·검증은 비동기로 처리하고 진행 상태를 보여준다.
- 회의 스크립트 본문은 로그에 남기지 않는다.
- 모델은 설정으로 바꾼다 (Ollama / Claude). 테스트는 fixture 응답을 쓴다.

## 보안 요구사항 (docs/THREAT-MODEL.md)
- [ ] S1. 작업 ID는 추측할 수 없는 값이다. 다른 작업 ID로 결과를 열람할 수 없다 (순번 대입 테스트).
- [ ] S2. 스크립트와 결과는 보관 기간이 지나면 삭제된다.
- [ ] S3. 입력 크기 상한(50,000자, 설정값)을 서버에서 검사한다. 정리 요청과 미리보기 API 모두에 적용하고, 넘으면 400으로 거부한다. 요청 본문 바이트 상한도 서버에 둔다 (F1 업로드 200KB 기준). 200KB = 204,800바이트(50,000자를 4바이트 문자로 채운 JSON도 통과하도록).
- [ ] S4. 정리 요청(작업 생성)에 요청 수 제한이 있다. 기본값 IP당 1시간 20회(설정값, 개발 프로필 200회), 넘으면 429. Claude 사용 시 하루 호출 상한이 있다. 미리보기 API 제한(IP당 분당 60회)은 별도 설정값이다 (F1).
- [ ] S5. 스크립트 속 지시문이 회의록 동작을 바꾸지 못한다. 그런 발언은 일반 발언으로만 다뤄진다 (eval 인젝션 케이스).
- [ ] S6. LLM 결과와 스크립트에 들어 있는 HTML·스크립트는 화면에서 실행되지 않는다.
- [ ] S7. API 키는 프론트 빌드 결과, 응답, 로그 어디에도 나오지 않는다.
