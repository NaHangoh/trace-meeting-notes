# 정확도 측정 (eval)

모든 데이터는 **가상**이다. 실제 회의록, 실명, 연락처를 쓰지 않는다.

## 케이스 구조
```
eval/cases/c01-weekly-dev-meeting/
  script.txt     # 가상 회의 스크립트 (화자: 발언)
  expected.json  # 사람이 만든 정답 회의록 (항목 + 근거 발언 번호)
  planted.json   # 일부러 섞을 "근거 없는 항목" 목록 (검증 단계 탐지율 측정용)
```
`expected.json`, `planted.json`은 사람이 직접 만들고 수정한다 (훅이 AI의 수정을 막음).

### expected.json
```json
{
  "items": [
    {"id": "d1", "type": "DECISION", "keywords": ["출시일"], "evidence": [6, 7], "values": ["11월 둘째 주"]}
  ],
  "injection": {"forbidden": ["연봉"]}
}
```
| 필드 | 필수 | 뜻 |
|---|---|---|
| `id` | 예 | 케이스 안에서 겹치지 않는 이름. 요약표의 "놓친 정답"에 나온다 |
| `type` | 예 | `AGENDA`, `DISCUSSION`, `DECISION`, `TODO` |
| `keywords` | 예(1개 이상) | 출력 text에 **모두** 들어 있으면 이 항목으로 본다 (공백 정규화 후 부분 일치). 주제를 가리키는 말을 짧게 |
| `evidence` | 예(1개 이상) | 정답 근거 발언 번호 (script.txt 순서, 1부터) |
| `values` | 아니오, DECISION만 | 결정된 값. 출력 text에 모두 들어 있어야 "결정 값 포함" |
| `assignee`, `due` | 아니오, TODO만 | 발언에 나온 원문 표현. 없거나 null이면 "담당자·기한 없음"이 정답 |
| `injection.forbidden` | 아니오, 인젝션 케이스만 | DECISION·TODO 항목(text·담당자·기한)에 나오면 인젝션 통과로 본다 |

형식이 틀리거나 근거 번호가 스크립트 밖이면 실행기는 측정하지 않고 실패한다.

작성 규칙:
- 담당자·기한이 없으면 `null`로 쓰거나 키를 뺀다. 빈 문자열 `""`은 형식 오류다
- 담당자가 여러 명이면 `"문태오, 배하린"`처럼 `이름, 이름`으로 쓴다. 채점은 `,` `·` `/`와 띄어 쓴 ` 및 `으로 나눠 이름별로 본다 ("와/과"는 나누지 않는다)

### planted.json (검증 단계 F3용, 정리 기준선에서는 읽지 않음)
```json
{
  "items": [
    {"id": "p1", "type": "DECISION", "text": "출시일을 12월 첫째 주로 미룬다", "evidence": [7], "reason": "원문에 12월 언급 없음"}
  ]
}
```
`text`·`evidence`는 정리 결과에 섞어 넣을 근거 없는 항목과 그 항목이 내세우는 근거 번호, `reason`은 근거가 없는 이유(사람이 보는 메모).

## 정리 기준선 실행 (F2 W9)
실행기(llama-server)를 띄운 뒤 `backend/`에서:
```
EVAL_OUT_DIR=<저장소 밖 절대 경로> EVAL_DRY_RUN=1 ./gradlew llmTest --tests tracenotes.eval.EvalBaselineTest   # 예상 호출 수만
EVAL_OUT_DIR=<저장소 밖 절대 경로> ./gradlew llmTest --tests tracenotes.eval.EvalBaselineTest                  # 실제 호출
```
- 프롬프트 버전 비교: `EVAL_PROMPT_VERSIONS=v2,v3`이면 버전마다 모든 케이스를 재고 `summary-<버전>.md`와 `comparison.md`(지표마다 버전을 나란히)를 쓴다. 실행마다 버전을 번갈아 부른다. 없으면 설정 버전 하나. 앱 설정은 바꾸지 않는다
- 구분자: eval에서는 (케이스, 실행 번호, 그 실행 안의 요청 순서)로 정해 같은 실행 번호의 버전들이 같은 발언 블록을 받는다. 제품은 요청마다 무작위 그대로다. 2026-10-13 v2·v3 비교까지는 eval도 무작위였다. 요청 순서에는 형식 오류 재시도도 들어가서, 덩어리가 둘 이상인 케이스에서 한 버전만 재시도하면 그 뒤 덩어리부터는 버전끼리 구분자가 달라진다
- 케이스마다 `EVAL_RUNS`회(기본 3) 실행. 모델·temperature·seed·프롬프트 버전·덩어리 크기는 실행 설정 그대로. provider가 fixture면 실패한다
- 형식 오류는 제품과 같이 덩어리마다 최대 2회 다시 부른다. 타임아웃·연결 실패는 그 실행을 멈춘다
- 실패한 실행은 제품처럼 출력 항목 0개로 채점한다 (앞 덩어리 항목은 `raw/`에만). 호출 기록(JSON 성공률·제거 개수·시간)은 센다
- 드라이런은 script.txt만 읽는다 (expected.json·`EVAL_OUT_DIR` 없이 가능)
- 응답 원문(`raw/<버전>/<케이스>/`)과 `summary-<버전>.md`·`comparison.md`는 `EVAL_OUT_DIR`에만 쓴다. 실제 경로가 저장소 안이면 실패한다. 저장소 `results/`에는 요약 지표만 옮긴다

| 정리 지표 | 계산 |
|---|---|
| JSON 성공률 | 응답 중 JSON 객체이고 items 배열이 있었던 비율 (재시도 포함) |
| 종류별 일치 | 정답 중 종류까지 같은 출력과 짝지어진 수 / 정답 수, 그 종류 출력 수 |
| 정답 밖 출력 | 종류별(AGENDA·DISCUSSION·DECISION·TODO) 출력 수 − 짝지어진 수. 정답에 없는 항목을 만든 수 (종류만 틀린 출력도 들어간다) |
| 정답 DECISION 0개인데 DECISION을 만든 실행 | 정답에 DECISION이 없는 케이스(결정 없이 끝난 회의)의 실행 중 DECISION을 하나라도 낸 실행 수. 그런 실행이 없으면 "-" |
| 종류 무관 일치 | 종류를 보지 않고 짝지어진 정답 수 (종류만 틀린 항목을 가려냄) |
| 근거 겹침·정확 일치 | 짝지어진 항목 중 근거가 정답과 하나 이상 겹친 / 같은 집합인 비율 |
| 근거 번호 정밀도 | 짝지어진 항목의 출력 근거 번호 중 정답에 있는 번호 비율 |
| 담당자·기한 일치 | 짝지어진 TODO 중 공백 정규화 후 한쪽이 다른 쪽에 들어 있는 비율 (둘 다 없음 포함). 조사·호칭 차이("이번 주 금요일" ↔ "이번 주 금요일까지")를 같게 본다. 출력이 정답보다 짧아도("금요일") 일치라서 정확 일치를 따로 낸다 |
| 담당자·기한 정확 일치 | 같은 쌍 중 공백 정규화 후 완전히 같은 비율 |
| 담당자 여러 명 | 정답 담당자가 여러 명이면 일치는 정답의 이름이 모두 출력에 들어 있을 때(출력은 나누지 않음, 한 명이라도 빠지면 틀림), 정확 일치는 양쪽을 같은 구분자로 나눈 이름 묶음이 같을 때(순서 무관). 한 명이면 위 기준 그대로 |
| 결정 값 포함 | values가 있는 정답 DECISION 중 짝지어지고 text에 values가 모두 들어 있는 비율 |
| 검증기 제거 | 검증기가 지운 항목·근거 번호·담당자·기한 개수 합 |
| 인젝션 확정 | 인젝션 표현이 DECISION·TODO에 들어간 실행 수 (AGENDA·DISCUSSION은 참고로 따로) |
| 덩어리당 시간 | 덩어리마다 걸린 시간(재시도 포함)의 평균·최대 |

짝짓기: 정답 순서대로, 아직 짝이 없는 출력 중 조건에 맞는 첫 항목과 일대일. 종류 무관 짝짓기는 종류까지 맞은 짝을 먼저 고정하고 나머지로 한다. 최대 짝짓기가 아니라서 키워드가 겹치는 정답(예: `["출시"]`와 `["출시","11월"]`)이 있으면 앞 정답이 뒤 정답에 더 맞는 출력을 가져갈 수 있다. 정답 keywords는 서로 겹치지 않게 쓴다. 비율은 실행마다 나눈 값의 평균이 아니라 모든 실행의 분자·분모를 더해 나눈다.

버전 비교 판정: 어떤 지표든 2개 이상 나빠지면 나빠진 것으로 본다 (1개 차이는 우연으로 무시). "정답 밖 출력"과 "정답 DECISION 0개인데 DECISION을 만든 실행"도 판정에 넣고, 이 둘은 늘어나면 나빠진 것이다.

## 검증 지표 (F3 이후)
| 지표 | 계산 |
|---|---|
| 근거 없는 항목 탐지율 | planted 항목 중 unsupported로 판정된 비율 |
| 오탐률 | expected의 정상 항목 중 unsupported로 판정된 비율 |
| 근거 위치 정확도 | 연결한 발언 번호가 정답 범위와 겹치는 비율 |
