작업: $ARGUMENTS

1. docs/plans/에서 해당 기능의 계획 파일을 먼저 읽고, 작업 단위 이름(W번호)으로 범위를 정한다. 계획 파일이 없으면 멈추고 묻는다.
2. 실패하는 테스트를 먼저 쓰고 실행해 실패를 확인한다.
3. 테스트를 통과시키는 최소한의 코드를 쓴다.
4. 전체 관련 테스트를 실행하고 결과를 그대로 보여준다. 통과하지 않으면 완료로 보고하지 않는다.
5. LLM이 들어가는 부분은 fixture 응답으로 테스트한다. 실제 모델 호출 테스트는 별도 태그(@Tag("llm"))로 분리한다.
6. 끝나면 reviewer 서브에이전트에게 diff 리뷰를 맡기고, 정확성과 SPEC 위반만 반영한다.
7. AI로 생성한 코드 중 직접 확인하고 고친 부분이 있으면 /ai-log에 남길지 사용자에게 묻는다.
