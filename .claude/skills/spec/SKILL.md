기능: $ARGUMENTS

1. docs/SPEC.md와 docs/adr/를 먼저 읽고, 이미 정해진 내용은 다시 묻지 않는다.
2. AskUserQuestion으로 한 번에 1~3개씩 인터뷰한다. 뻔한 질문은 빼고, 사용자가 놓쳤을 부분을 묻는다.
   - 사용자 흐름과 화면
   - 입력과 출력 형식, 실패했을 때의 동작
   - 엣지 케이스 (긴 스크립트, 화자 없음, 빈 입력, LLM 응답 오류)
   - 범위 밖으로 둘 것
3. 정리한 명세를 보여주고 확인받은 뒤 docs/SPEC.md에 추가한다. 형식:
   - 목적 / 사용자 흐름 / 입력·출력 / 수용 기준(테스트로 확인 가능한 문장) / 범위 밖
4. 수용 기준은 반드시 테스트로 확인할 수 있게 쓴다. "잘 동작한다" 같은 문장은 쓰지 않는다.
