# 테스트 규칙

- 기능은 실패하는 테스트부터 쓴다. SPEC의 수용 기준 하나당 테스트 하나 이상.
- "완료"라고 말하기 전에 테스트를 실행하고 실행 명령과 결과를 그대로 보여준다.
- 테스트를 통과시키려고 테스트를 지우거나 약하게 바꾸지 않는다. 바꿔야 하면 이유를 말하고 확인받는다.
- 실제 LLM이 필요한 테스트는 `@Tag("llm")`(백엔드) 또는 별도 스크립트로 분리하고 기본 실행에서 제외한다.
- 내보내기(docx 등) 테스트는 파일을 다시 열어 내용을 확인한다. 근거·검증 표시가 들어가지 않았는지도 검사한다.
- 프론트엔드는 핵심 흐름(입력 → 결과 검토 → 확정 → 다운로드)을 컴포넌트 테스트로 확인한다.
- `@Disabled`, `.skip`, `.only`, `xit` 추가는 훅이 막는다. 테스트가 실패하면 원인을 보고하고 사용자와 정한다.
- 테스트 코드에서 `.env`나 실제 환경 변수 비밀값을 읽지 않는다. 필요한 값은 테스트용 가짜 값을 쓴다.
- 테스트의 보이지 않는 문자(BOM, NBSP, 전각 공백, 폭 없는 공백)는 코드 포인트로 만든다. Java: Character.toString(0x00A0), TS: String.fromCharCode(0x00A0). 문자열 이스케이프(\u....)는 편집 도구가 실제 문자로 바꿀 수 있어 새 코드에 쓰지 않는다. 기존 이스케이프는 고치지 않고, 커밋 전 아래 패턴으로 바이트 검사한다: '302 240|343 200 200|342 200 213|357 273 277'
- 소스·테스트 파일은 편집 도구로만 쓴다. Python·셸 스크립트로 파일을 만들거나 덮어쓰지 않는다 (훅 검사 우회됨).
